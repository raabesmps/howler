# Howler v1.0.0

[English](v1.0.0.md) · [Português](../../pt-BR/project/releases/v1.0.0.md)

Released 2026-11-24. Live at <https://howler.aquifunciona.dev.br>. The full list of changes is in the [changelog](../../../CHANGELOG.md); this page is the story: what the release is, what it does well, and where it is honest about its limits.

## What it is

You write up to 140 characters and get a one-time link. Whoever opens it sees a closed envelope. It rumbles, tears open and screams the message in a hysterical furious mother's voice, shaking with every shout, then closes, burns from the centre outward and falls into powder. The link works once; afterwards the message no longer exists on the server and the link only says it was delivered.

It is a fan project: no affiliation with Warner Bros. or J.K. Rowling, no franchise names, art or sounds. The voice is a character, never an impersonation.

## What this release does well

- **The single use is real.** Opening runs in a transaction with a row lock. A test starts 12 separate processes against PostgreSQL and asserts that exactly one gets the message; it fails if the lock is removed. Link previews cannot burn a howler, because opening is a `POST` and crawlers only `GET`.
- **It forgets on purpose.** Tokens are stored only as hashes, opening and expiry delete the message, database constraints forbid keeping content on a finished howler, and no IP or device is stored with it.
- **The voice is part of the engineering.** One pinned model snapshot and one voice, with a fixed direction; the model's transcript must match the text word for word; the audio is made once at creation, delivered with the opening and deleted; the device cleans and levels it. When anything fails, the browser reads the message instead, so a message is never lost.
- **It stays smooth.** The burn is a per-pixel canvas effect that watches its own frame time and steps down through four quality levels on slow phones. The envelope shakes with the real loudness of the audio.
- **It is bounded.** Per-IP limits, a daily budget of server voices, a 140-character limit, and a body-size limit at the edge keep abuse and the OpenAI bill inside known numbers (about 1.5 US cents per howler).
- **It was tested like a product.** PHPUnit on PostgreSQL, Vitest, and Playwright on a phone viewport: the whole journey, a second open from anywhere, connection failures, keyboard-only and reduced motion, the sound controls and axe checks on every screen.
- **Releases are safe to make and to undo.** A release is a manual workflow that waits for an approval, needs a green CI, takes a database dump first, and ends with a smoke test that lives a howler's whole life against the real site, including an expiry and the purge. If the new version is unhealthy or the smoke test fails, the previous version comes back by itself. Rolling back by hand takes one command.
- **The decisions are written down.** Five ADRs, an OpenAPI contract, a development guide, a testing guide and a deployment runbook, all in English with a Portuguese twin, with a checker in CI that keeps the links and the twins honest.

## How it was built

In checkpoints, one pull request each, merged without squash and tagged (`cp0` to `cp10`, then `v1.0.0`): the repository and its rules, the visual design, a frontend-only prototype of the envelope, the burn and the voice, the data model, the single-use API, the integration, the quality work, the staging deploy and finally production. Some changes of direction are in the plan itself ([PLAN.md](../PLAN.md), "Changes to the plan"): the sender never chooses the voice, the voice moved from the browser to the server, and production took over the one VM.

## Known limits

Read these before sending the link to many people.

- **The production machine is small.** It is a Google Cloud e2-micro (1 GB of memory) with swap. It runs the whole stack, and it is thin for a burst of visitors. The runbook ([section 1](../../guides/DEPLOYMENT.md)) says how to move to a bigger machine (stop, change the machine type, start; the address and the disk stay) and to raise the PHP-FPM pool.
- **Sentry is not switched on yet.** The code is there, scrubbed (see [ADR-005](../../decisions/ADR-005-error-monitoring.md)), but it stays off until the owner creates the projects and checks a real event. Until then errors are only in the container logs.
- **SSH is open to the internet** (key login only). Restricting port 22 to the owner's address is a one-line firewall change that is still to do.
- **Only Chromium is tested.** Safari and Firefox are not in the end-to-end suite. The audio code uses the Web Audio API, which they support, but nothing here proves it.
- **Nobody can hear the tests.** How the voice and the effects sound was judged by ear, once, and is fixed by a pinned model version; a retired version would need the tone to be checked again ([ADR-002](../../decisions/ADR-002-voice-approach.md)).
- **The interface is in English** (the message can be in any language, and the voice handles at least English and Brazilian Portuguese).
- **A link cannot be taken back.** By design there are no accounts: if the sender loses the link, it cannot be shown again, and anyone who holds a link can open it.
- **The layout will be refined.** The design is approved as a first version; polishing it is the next piece of work.
- **Some default Laravel tables are unused** (users, queues). They are harmless and were left alone to avoid touching deployed tables.

## Running it, and undoing it

- Locally: the [development guide](../../guides/DEVELOPMENT.md).
- A release: **Actions, Deploy production, Run workflow** on `main`, then approve. The [runbook](../../guides/DEPLOYMENT.md) has everything else: the VM, the secrets, rollback, monitoring and backups.
- Costs to keep an eye on: the VM, and the voice (about 1.5 US cents per howler, capped per day by `HOWLER_VOICE_DAILY_LIMIT`, with a monthly spend limit on the OpenAI account as the second line).
